- **Human gold:** The `ca.crt` path fix above is good. One related issue left in this same file.

**Problem:** `--cluster-gateway-ca-file` is set for `direct` + `secureTLS`, but the CA volume mount (`tls-cert-vol-cg`) only renders inside `admissionWebhooks.enabled`. With admission off, the controller still gets the CA arg and then crashes:

```
open /cluster-gateway-tls-cert/ca.crt: no such file or directory
```

**Where:** `charts/vela-core/templates/kubevela-controller.yaml` around the `volumeMounts` / `volumes` block (~L344-L392 on this branch). Ports and probes can stay under admission.

**Change:** gate `tls-cert-vol-cg` on multicluster + secureTLS + direct, not on admission. Something like:

```yaml
{{- $needAdmissionTLS := .Values.admissionWebhooks.enabled }}
{{- $needClusterGatewayTLS := and .Values.multicluster.enabled .Values.multicluster.clusterGateway.secureTLS.enabled .Values.multicluster.clusterGateway.direct }}

{{ if .Values.admissionWebhooks.enabled }}
ports: ...
probes: ...
{{ end }}

{{ if or $needAdmissionTLS $needClusterGatewayTLS }}
volumeMounts:
  {{ if $needAdmissionTLS }}
  - name: tls-cert-vol
    mountPath: {{ .Values.admissionWebhooks.certificate.mountPath }}
    readOnly: true
  {{ end }}
  {{ if $needClusterGatewayTLS }}
  - name: tls-cert-vol-cg
    mountPath: /cluster-gateway-tls-cert
    readOnly: true
  {{ end }}
{{ end }}

{{ if or $needAdmissionTLS $needClusterGatewayTLS }}
volumes:
  {{ if $needAdmissionTLS }}
  - name: tls-cert-vol
    secret:
      secretName: {{ template "kubevela.fullname" . }}-admission
  {{ end }}
  {{ if $needClusterGatewayTLS }}
  - name: tls-cert-vol-cg
    secret:
      secretName: {{ template "kubevela.fullname" . }}-cluster-gateway-tls-v2
  {{ end }}
{{ end }}
```

I tried this locally on k3d: `admissionWebhooks.enabled=false` + direct + secureTLS + cert-manager failed before the change and came up Ready after. Default `admissionWebhooks.enabled=true` still works.
